# تست فاز ۴

نسخه ۰.۵.۰ را نصب و پنجره را Reload کن.

1. فرمان **Templates: Connect GitHub Sync** را اجرا کن. حساب GitHub خود VS Code استفاده می‌شود؛ ممکن است اجازه دسترسی به ریپو لازم باشد.
2. برای تست، یک ریپوی خصوصی اختصاصی بساز یا ریپوی خصوصی موجود با حداقل یک commit را انتخاب کن.
3. یک گروه کوچک ذخیره کن و **Templates: Sync Now** را بزن. فایل‌های واقعی زیر `templates/<group-id>/` و متادیتا در `.vstemplater/manifest.json` باید دیده شوند. محتوای فایل‌ها نباید داخل manifest باشد.
4. روی دستگاه یا پروفایل دوم به همان ریپو متصل شو؛ گروه باید دریافت شود. تغییر و حذف یک فایل/گروه باید بین دو دستگاه منتقل شود.
5. آفلاین تغییر بده، سپس متصل شو؛ سینک در تلاش بعدی یا با Sync Now انجام شود.
6. در هر دو دستگاه، قبل از سینک یک گروه را متفاوت تغییر بده. با Sync Now انتخاب نسخه نمایش داده شود. انتخاب برای کل گروه است؛ لغو نباید هیچ‌کدام را بازنویسی کند.
7. فایل تمپلیت ذخیره‌نشده باید سینک را متوقف کند. Save کن و دوباره تلاش کن.
8. **Templates: Disconnect GitHub Sync** باید سینک خودکار را قطع کند و داده‌های محلی و ریپو باقی بمانند.

9. برای مهاجرت، ابتدا همه دستگاه‌ها و پنجره‌ها را به نسخه جدید ارتقا بده. Sync Now باید فایل‌های واقعی را بسازد و JSON قبلی را در همان commit حذف کند؛ نسخه قدیمی در تاریخچه Git باقی می‌ماند. اتصال دوباره لازم نیست.
10. گروهی با حجم بیش از ۷۵۰ کیلوبایت، فایل باینری و پوشه خالی سینک کن و روی دستگاه دوم ایمپورت کن. بایت‌ها و مسیرها باید حفظ شوند.
11. سینک بدون تغییر نباید commit جدید بسازد. تغییر یک فایل باید فقط همان فایل را در diff نشان بدهد. فایل‌های نامرتبط ریپو باید حفظ شوند.

محدودیت قدیمی حجم مجموعه حذف شده؛ محدودیت‌های GitHub و حافظه همچنان برقرارند. تعارض در سطح گروه حل می‌شود. تست‌های شبکه شبیه‌سازی‌شده‌اند؛ ورود و رفت‌وبرگشت واقعی GitHub هنوز نیازمند همین تست دستی است.
