# راهنمای استفاده از VS Templater

VS Templater فایل‌ها و پوشه‌های پروژه را در گروه‌های نام‌دار ذخیره می‌کند تا بتوانید آن‌ها را در پروژه‌های دیگر استفاده کنید. هر تمپلیت یک کپی مستقل است؛ تغییر فایل اصلی، تمپلیت ذخیره‌شده را تغییر نمی‌دهد.

این راهنما برای نسخهٔ **۰.۵.۲** است. نام فرمان‌ها و پیام‌های اکستنشن انگلیسی هستند.

## نصب و شروع

1. در VS Code، Command Palette را با `Cmd+Shift+P` در macOS یا `Ctrl+Shift+P` در Windows/Linux باز کنید.
2. فرمان **Extensions: Install from VSIX...** را اجرا و فایل `vstemplater-0.5.2.vsix` را انتخاب کنید.
3. بعد از ارتقا، همهٔ پنجره‌های VS Code را ببندید و دوباره باز کنید؛ به‌خصوص هنگام ارتقا از نسخهٔ ۰.۴ به نسخه‌های جدید، نباید یک پنجره همچنان سینک قدیمی را اجرا کند.
4. یک پوشهٔ پروژهٔ محلی و مورد اعتماد باز کنید. بخش **Templates** در Explorer دیده می‌شود.

برای ساخت فایل نصب از سورس:

```sh
npm ci
npm run check
npm test
npm run package
```

فایل VSIX در ریشهٔ پروژه ساخته می‌شود. برای اجرای نسخهٔ توسعه، پروژه را در VS Code باز کنید و `F5` بزنید.

## ساخت گروه و اضافه‌کردن فایل

1. در Explorer روی فایل یا پوشهٔ موردنظر کلیک راست کنید.
2. **Add to Templates** را انتخاب کنید.
3. یک گروه موجود را انتخاب کنید یا گروه جدیدی بسازید و نام بدهید.
4. گروه در بخش **Templates** ظاهر می‌شود؛ با بازکردن آن می‌توانید مسیرها و فایل‌ها را ببینید.

مسیر والدها نسبت به ریشهٔ پروژه ذخیره می‌شود. برای مثال، اضافه‌کردن `src/components/Button` همین مسیر را نگه می‌دارد. اگر دوباره به همان گروه اضافه کنید، فایل‌های هم‌مسیر به‌روزرسانی و فایل‌های جدید اضافه می‌شوند. فایل‌های قدیمی که دیگر در پوشهٔ مبدأ نیستند، خودکار از گروه پاک نمی‌شوند؛ برای آن‌ها از **Delete** استفاده کنید.

## واردکردن تمپلیت در پروژه

روی پوشهٔ مقصد کلیک راست کنید و **Import from Template** را بزنید. گروه را از فهرست انتخاب کنید و یکی از روش‌های زیر را تعیین کنید:

| انتخاب | نتیجه |
| --- | --- |
| **Keep original paths** | مسیر ذخیره‌شده زیر مقصد بازسازی می‌شود. |
| **Choose a new path** | پوشهٔ مقصد را در پروژه انتخاب می‌کنید؛ اگر گروه یک ریشه داشته باشد، والدهای آن ریشه حذف می‌شوند. |

مثلاً گروه `UI` فقط پوشهٔ `src/components/Button` را دارد:

```text
مسیر اصلی + مقصد packages/web:
packages/web/src/components/Button/...

مسیر جدید + مقصد packages/web:
packages/web/Button/...
```

پوشه‌ای با نام گروه `UI` ساخته نمی‌شود؛ فقط محتوای گروه وارد می‌شود. گروه‌های دارای چند ریشه، مسیرهای نسبی خود را در مقصد جدید حفظ می‌کنند. انتخاب‌گر مقصد، پوشهٔ موجود را انتخاب می‌کند؛ در صورت نیاز ابتدا پوشهٔ جدید را بسازید.

کلیک راست روی یک فایل، پوشهٔ والد آن را مقصد قرار می‌دهد. هنگام اجرای فرمان از Command Palette، مقصد را انتخاب می‌کنید. در پروژه‌های چندریشه‌ای نیز ممکن است انتخاب پروژه لازم باشد.

پوشه‌های موجود با محتوای ورودی ادغام می‌شوند. جایگزینی فایل موجود نیازمند تأیید است و لغو تأیید، مقصد را تغییر نمی‌دهد. فایل‌های مقصد با تغییرات ذخیره‌نشده باید ابتدا Save یا بسته شوند.

## مدیریت گروه‌ها و فایل‌ها

در بخش **Templates**، روی گروه، پوشه یا فایل کلیک راست کنید:

| فرمان | کاربرد |
| --- | --- |
| **Import into Project** | فقط همان گروه، پوشه یا فایل را وارد پروژه می‌کند. |
| **Rename** | نام مورد انتخاب‌شده را عوض می‌کند؛ تغییر نام پوشه مسیر فرزندان را هم تغییر می‌دهد. |
| **Delete** | بعد از تأیید، مورد انتخاب‌شده را حذف می‌کند؛ حذف پوشه شامل فرزندان آن است. |
| **Edit Template File** | فایل تمپلیت را در ویرایشگر باز می‌کند. |

روی فایل کلیک کنید، آن را ویرایش کنید و Save بزنید تا نسخهٔ ذخیره‌شدهٔ تمپلیت تغییر کند. فایل اصلی پروژه دست‌نخورده باقی می‌ماند. تغییرات ذخیره‌نشدهٔ تمپلیت، عملیات حذف، تغییر نام یا سینک مرتبط را متوقف می‌کند.

حذف آخرین فایل یک گروه، گروه خالی باقی می‌گذارد؛ برای حذف خود گروه، روی نام آن **Delete** بزنید. دکمهٔ **Refresh Templates** فهرست محلی را دوباره می‌خواند؛ این فرمان سینک یا بازیابی از GitHub انجام نمی‌دهد.

مشاهده و مدیریت تمپلیت‌های ذخیره‌شده بدون پروژهٔ باز ممکن است. **Add** و **Import** به پروژهٔ محلی باز نیاز دارند؛ در غیر این صورت پیام `Open a project first.` نمایش داده می‌شود.

## اتصال به GitHub

1. در Command Palette فرمان **Templates: Connect GitHub Sync** را اجرا کنید.
2. از حساب GitHub خود VS Code استفاده کنید و در صورت درخواست، دسترسی ریپازیتوری را بدهید. اکستنشن توکن را خودش ذخیره نمی‌کند.
3. **Create private repository** را برای ایجاد ریپوی خصوصی انتخاب کنید، یا با **Use existing private repository** نشانی `owner/name` بدهید.
4. ریپوی موجود باید دسترسی نوشتن و یک شاخهٔ پیش‌فرض با حداقل یک commit داشته باشد.
5. با **Templates: Sync Now** وضعیت را بررسی کنید. پیام موفقیت `Templates synced with GitHub.` است.

ریپوی سورس اکستنشن و ریپوی ذخیرهٔ تمپلیت‌ها کاربرد متفاوت دارند؛ برای تمپلیت‌ها یک ریپوی خصوصی اختصاصی انتخاب کنید. این قابلیت از ورود GitHub در VS Code استفاده می‌کند، اما انتقال تمپلیت‌ها توسط خود اکستنشن انجام می‌شود و بخشی از سرویس Settings Sync نیست.

ساختار ذخیره‌سازی روی GitHub:

```text
.vstemplater/
  manifest.json
templates/
  <group-id>/
    src/components/Button/...
```

فایل‌ها واقعی و قابل مشاهده‌اند. manifest فقط نام گروه‌ها، مسیرها، حالت فایل‌ها و اطلاعات پوشه‌های خالی را نگه می‌دارد. شناسهٔ گروه در ریپوی سینک به کار می‌رود و موقع Import پوشهٔ اضافی ایجاد نمی‌کند. محتوای فایل‌ها توسط اکستنشن رمزگذاری نمی‌شود.

سینک هنگام شروع، کمی بعد از تغییر محلی و هر دقیقه اجرا می‌شود. در حالت آفلاین، داده‌ها محلی می‌مانند و تلاش مجدد انجام می‌شود. برای دستگاه دوم، همان نسخهٔ اکستنشن را نصب و همان ریپو را متصل کنید.

## تعارض، حذف و قطع اتصال

اگر یک گروه در دو طرف تغییر کرده باشد، سینک خودکار متوقف می‌شود. **Sync Now** دو گزینه می‌دهد:

- **Keep local group**: نسخهٔ کامل گروه محلی انتخاب می‌شود.
- **Use GitHub group**: نسخهٔ کامل گروه GitHub انتخاب می‌شود.

انتخاب در سطح کل گروه است، نه ادغام خط‌به‌خط فایل‌ها. لغو انتخاب، هیچ نسخه‌ای را بازنویسی نمی‌کند.

اگر نتیجهٔ سینک حذف همهٔ گروه‌های باقی‌مانده باشد، سینک خودکار متوقف می‌شود. در سینک دستی، **Keep remaining templates** دادهٔ موجود را به طرف خالی برمی‌گرداند. فقط وقتی حذف کامل عمدی است، **Delete all synced templates** را انتخاب کنید.

**Templates: Disconnect GitHub Sync** اتصال را قطع می‌کند و دادهٔ محلی و ریپو باقی می‌مانند. قبل از تغییر حساب یا ریپو، اتصال را قطع کنید.

## رفع مشکل

| وضعیت | اقدام |
| --- | --- |
| پروژه باز نیست | یک پوشهٔ پروژهٔ محلی باز کنید. |
| فایل تمپلیت ذخیره‌نشده است | Save کنید یا پس از نگه‌داشتن تغییرات لازم، ویرایشگر را ببندید. |
| گروه در پنجرهٔ دیگری تغییر کرده | Refresh بزنید و مورد را دوباره انتخاب کنید. برای ویرایشگر قدیمی، ابتدا متن ذخیره‌نشده را نگه دارید و فایل را دوباره باز کنید. |
| خطای شبکه یا دسترسی GitHub | اتصال شبکه، حساب و دسترسی ریپوی خصوصی را بررسی و Sync Now را دوباره اجرا کنید. |
| JSON قدیمی کنار manifest ظاهر شده | همهٔ دستگاه‌ها و پنجره‌ها را به‌روز و دوباره راه‌اندازی کنید. قبل از حذف JSON قدیمی، محتوایش را با نسخهٔ جدید مقایسه و نسخهٔ پشتیبان تهیه کنید. |
| manifest گم شده | سینک را متوقف کنید و نسخهٔ سالم آن را همراه فایل‌های مربوط از تاریخچهٔ Git بازیابی کنید. |
| گروه‌ها ناپدید شده‌اند | Refresh دادهٔ حذف‌شده را بازیابی نمی‌کند. اتصال سینک را قطع و آخرین commit سالم ریپوی تمپلیت‌ها را بررسی کنید. |

برای بازیابی، نسخهٔ سالم را ابتدا در پوشه‌ای جدا دریافت و فایل‌ها را بررسی کنید. manifest و فایل‌های متعلق به آن باید با هم سازگار باشند. سپس بازیابی را با یک commit جدید انجام دهید تا تاریخچه حفظ شود. پیش از اتصال مجدد، مطمئن شوید همهٔ کلاینت‌ها نسخهٔ جدید را اجرا می‌کنند.

## محدودیت‌ها

- فعلاً پروژه‌های محلی دسکتاپ پشتیبانی می‌شوند؛ SSH، WSL، کانتینرها و محیط‌های مجازی در محدودهٔ پشتیبانی نیستند.
- `.git`، `node_modules`، `.env` و `.env.*` به‌جز `.env.example` هنگام جمع‌آوری کنار گذاشته می‌شوند؛ `.gitignore` مبنای این فیلتر نیست.
- لینک نمادین و فایل ویژه پشتیبانی نمی‌شوند. مسیرهای غیرقابل‌انتقال بین سیستم‌عامل‌ها و نام‌های متعارض از نظر بزرگی حروف رد می‌شوند.
- محدودیت قبلی ۷۵۰ کیلوبایت حذف شده، ولی محدودیت‌های GitHub و حافظهٔ دستگاه همچنان برقرارند.
- هر فایل جداگانه به‌صورت اتمی Import می‌شود؛ کل گروه یک تراکنش نیست. اگر کپی نیمه‌کاره بماند، خطا تعداد فایل‌های واردشده را گزارش می‌کند.
- فایل‌های موجود را می‌توان روی GitHub ویرایش کرد؛ افزودن، حذف و تغییر نام را از اکستنشن انجام دهید تا manifest هم به‌روز شود.
